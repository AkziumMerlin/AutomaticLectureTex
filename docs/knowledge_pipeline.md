# Knowledge-backed lecture reconstruction

The default notes pipeline is deliberately not `chunk -> prose -> concatenate`.
Technical transcript windows are only redundant evidence containers.

```text
transcript + selected frames
        |
        v
 overlapping evidence windows
        |
        v
 local evidence extraction
        |
        v
 overlap reconciliation
        |
        v
 canonical observations
        |
        v
 online semantic episode tracker
        |
        v
 event-sourced LectureKnowledgeBase
   - canonical observations + aliases
   - SemanticEpisode sequence
   - claims derived from observations
   - correction/retraction history
   - episode-scoped typed symbols
        |
        v
 EpisodeHierarchyBuilder
 (boundaries over immutable episode leaves only)
        |
        v
 deterministic section projection
        |
        v
 section synthesis
        |
        v
 document-level validation
        |
        v
 LectureIR -> deterministic LaTeX
```

## Technical windows are not semantic units

`notes.chunk_target_seconds` and `notes.chunk_overlap_seconds` only control evidence collection. A
proof, definition, example, or correction can start in one technical window and end in the next.
The overlap is intentional: the same interval may be seen twice so that neither side of a technical
boundary loses context.

Before any semantic state is updated, repeated observations from overlapping windows are reconciled.
The host compares temporal overlap plus formula/prose similarity. Repeated observations become one
canonical observation with multiple `window_ids`/`evidence_refs`; discarded raw ids are retained in
`observation_aliases`. Thus downstream state never has to treat two overlapping window summaries as
two independent pieces of lecture content.

## Semantic episodes are the structural source of truth

The core object is `SemanticEpisode`, not an outline section and not a chunk. During the video pass an
LLM may only place boundaries before canonical observations and optionally mark an episode as closed.
The host assigns every canonical observation to exactly one episode. With no new boundary, the next
window naturally continues the currently open episode.

Typical episode kinds are definition, theorem, proof, derivation, example, notation, remark, and
larger topic transitions. A technical window boundary has no structural meaning.

Canonical claims are not freely generated by a separate LLM pass. They are derived from canonical
observations after those observations have been assigned to episodes. Consequently a claim has an
`episode_id`, and its `scope` is the episode that contains its evidence. This is also how symbol scope
is chosen: the model may infer a symbol meaning/type, but the host derives its namespace from the
episode containing the cited evidence.

Explicit lecturer corrections/retractions are state transitions over evidence. A correction with a
resolvable `target_observation_id` supersedes the active claim derived from that target; a retraction
marks it retracted. The original observation remains in the event history for provenance.

`anchors` remain in `lecture_kb.json` only as a backward-compatible view derived deterministically
from episode starts. They are no longer an independent planning structure.

## Hierarchy is grouping, not free-form outline generation

After the complete lecture has been processed, `EpisodeHierarchyBuilder` receives the fixed ordered
sequence of semantic episodes. It may return only boundaries before existing episode ids, at two
levels: `topic` and `subtopic`.

The host then constructs sections by grouping adjacent episode leaves. Time ranges, claim ids, and
evidence ids are unions of the underlying episodes. The hierarchy model cannot invent a section,
remove an episode, reorder content, manufacture timestamps, or independently choose provenance.
Every episode therefore appears exactly once in the final top-level section sequence by construction,
not because a post-hoc gate checked a free-form outline.

## Section synthesis and validation

A section writer receives one fixed topic group plus its ordered semantic episodes, active claims,
canonical observations, episode-scoped symbols, and local transcript context. It may turn that state
into readable LaTeX blocks but must not repartition the section or add unsupported textbook material.

The document-level validator sees the same episode graph. It is intentionally downstream of
structure: it should catch rendering/synthesis inconsistencies such as a superseded formula surviving
into prose, duplicated rendered content, or a symbol meaning leaking between episode scopes. It must
not use unchecked/reconstructed claims as permission to complete missing mathematics from general
knowledge.

## Artifacts

A knowledge-mode run writes:

```text
work/<lecture>/
├── transcript.json
├── lecture_kb.json
├── episode_hierarchy.json
├── lecture_outline.json       # deterministic projection of episode hierarchy
├── global_validation.json
├── lecture_ir.json
├── run_metrics.json
├── knowledge_windows/
│   └── window_XXXX.json       # observations + episode boundary update
├── knowledge_sections/
│   └── topic_XXX.json
└── frames/
```

Window artifacts are fingerprinted against the semantic state before that window. Cache version 2
invalidates the older claim/anchor/free-form-outline artifacts because they cannot be replayed into
the new episode graph without changing semantics.

## Main controls

```yaml
notes:
  architecture: knowledge
  chunk_target_seconds: 480
  chunk_overlap_seconds: 120
  boundary_context_seconds: 120
  knowledge_max_active_claims: 160
  knowledge_recent_observations: 80
  global_validation: true
  global_validation_apply_threshold: 0.85
```

`architecture: legacy` keeps the previous sequential `finalize_chunk` path for regression testing and
comparison. It uses non-overlapping chunks and writes the older `chunks/chunk_XXXX.json` artifacts.
